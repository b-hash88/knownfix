Timing assumptions
Every attempt is unsuccessful and consumes its full timeout. Each wait starts after the previous failure. The first attempt starts at zero; it has no wait.
Retry delay = min(cap, initial delay × multiplier^(retry number − 1)). Full jitter uses a uniform range from zero to that delay; expected wait is half the capped delay. Ranges are bounds, not a random sample or a percentile forecast.
The budget check uses the latest modeled finish. Queue latency, network overhead, provider retry rules and Retry-After are excluded. This JSON is a planning record, not a provider configuration.

When to investigate further
Expected duration is not a deadline
Use the maximum modeled finish for the budget check. Full jitter changes the range and expected wait; it does not guarantee a delivery time.
Your provider uses Retry-After
That policy is outside this calculator. Compare the exported plan with the actual provider rules before implementing or replaying anything.
